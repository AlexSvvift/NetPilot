# NetPilot

NetPilot - учебный portfolio-проект на Python для мониторинга серверов,
сайтов и VPN-точек. Сервис периодически проверяет доступность целей, сохраняет
результаты в SQLite и показывает состояние через web-панель и REST API.

Проект рассчитан на демонстрацию навыков junior Python backend-разработчика:
FastAPI, Pydantic, SQLAlchemy, асинхронные проверки, фоновые задачи, Docker,
тестирование и понятная документация.

## Что умеет проект

- проверять HTTP/HTTPS-сайты;
- проверять TCP-порты серверов и VPN-сервисов;
- проверять UDP-порты;
- запускать периодический мониторинг в фоне;
- сохранять историю проверок в SQLite;
- показывать доступность, время ответа и последнюю ошибку;
- добавлять, изменять, включать и удалять цели через web-интерфейс;
- защищать изменяющие запросы заголовком `X-API-Key`;
- отдавать REST API и документацию Swagger/OpenAPI;
- запускаться локально или через Docker Compose.

## Внешний вид

После запуска откройте в браузере:

```text
http://127.0.0.1:8000
```

Слева находятся показатели состояния, справа - список целей. Новую цель можно
добавить через форму: для HTTP указывается URL, для TCP/UDP - адрес сервера и
порт. Кнопка проверки запускает проверку сразу, не дожидаясь расписания.

## Быстрый запуск в Windows

В PowerShell перейдите в папку проекта:

```powershell
cd D:\PythonProjectXXX\VPN
```

Создайте виртуальное окружение и установите зависимости:

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

Если команда `py` недоступна, используйте установленный Python из PyCharm или
полный путь к `python.exe`.

Создайте файл настроек из примера:

```powershell
Copy-Item .env.example .env
```

Запустите приложение:

```powershell
python -m uvicorn app.main:app --reload
```

Откройте:

- web-панель: `http://127.0.0.1:8000`;
- Swagger: `http://127.0.0.1:8000/docs`;
- проверка здоровья: `http://127.0.0.1:8000/api/health`.

## Первый сценарий

1. Откройте web-панель.
2. Введите имя `My website`.
3. Выберите тип `HTTP`.
4. Укажите `https://example.com`.
5. Нажмите `Добавить цель`.
6. Нажмите кнопку проверки в строке цели.
7. Посмотрите статус `UP`, время ответа и историю.

Для проверки своего сервера выберите `TCP`, например:

```text
Адрес: 192.168.1.1
Порт: 443
```

## Примеры API

Получить список целей:

```powershell
Invoke-RestMethod http://127.0.0.1:8000/api/targets
```

Добавить HTTP-цель:

```powershell
$headers = @{ "X-API-Key" = "change-me" }
$body = @{
    name = "My website"
    kind = "http"
    url = "https://example.com"
    interval_seconds = 60
    timeout_seconds = 5
} | ConvertTo-Json

Invoke-RestMethod `
    -Uri http://127.0.0.1:8000/api/targets `
    -Method Post `
    -Headers $headers `
    -ContentType "application/json" `
    -Body $body
```

Запустить ручную проверку:

```powershell
Invoke-RestMethod `
    -Uri http://127.0.0.1:8000/api/targets/1/check `
    -Method Post `
    -Headers $headers
```

Полный список методов и интерактивные примеры находятся в Swagger:
`http://127.0.0.1:8000/docs`.

## Проверка качества

Установите зависимости и запустите тесты:

```powershell
python -m pytest
```

Тесты проверяют:

- endpoint здоровья;
- авторизацию изменяющих API-запросов;
- полный CRUD-цикл цели;
- валидацию входных данных;
- успешную проверку локального TCP-порта.

## Запуск через Docker

Установите Docker Desktop, затем выполните:

```powershell

docker compose up --build
```

После запуска приложение доступно на `http://127.0.0.1:8000`. Остановить его:

```powershell

```

## Настройки

Настройки читаются из `.env`. Основные переменные:

| Переменная | Назначение | Пример |
| --- | --- | --- |
| `DATABASE_URL` | строка подключения к базе | `sqlite:///./data/netpilot.db` |
| `API_KEY` | ключ для POST/PATCH/DELETE | `change-me` |
| `MONITORING_ENABLED` | включить фоновые проверки | `true` |
| `SCHEDULER_TICK_SECONDS` | как часто просматривать цели | `5` |
| `LOG_LEVEL` | уровень логирования | `INFO` |
| `CORS_ORIGINS` | разрешенные web-источники | `http://127.0.0.1:8000` |

В реальном проекте файл `.env` с секретами не коммитят в Git. В репозитории
хранится только `.env.example`.

## Как рассказывать о проекте

Короткая формулировка для резюме:

> Разработал сервис мониторинга серверов и VPN-точек на FastAPI. Реализовал
> HTTP/TCP/UDP health checks, фоновый планировщик, хранение истории в SQLite,
> REST API, web-панель, API-авторизацию, Docker Compose и pytest-тесты.

На собеседовании полезно объяснить:

1. Почему проверки сделаны асинхронными: сервис может одновременно ждать ответы
   от нескольких сетевых целей.
2. Зачем нужен планировщик: пользователь не должен запускать каждую проверку
   вручную.
3. Зачем нужен репозиторий: работа с базой отделена от HTTP-слоя.
4. Зачем нужна Pydantic-валидация: неправильные URL, порты и интервалы
   отбрасываются до записи в базу.
5. Почему `API_KEY` не является полноценной авторизацией: для production нужен
   пользовательский вход, роли, хеширование паролей и HTTPS.

## Ограничения учебной версии

- SQLite подходит для локального запуска и небольшого количества целей.
- UDP-проверка подтверждает отправку датаграммы, потому что UDP не гарантирует
  ответ от сервера.
- Планировщик работает внутри процесса приложения; для большой нагрузки лучше
  вынести задачи в отдельный worker.
- Для production понадобятся PostgreSQL, миграции Alembic, Prometheus/Grafana,
  структурированные логи и полноценная система пользователей.
